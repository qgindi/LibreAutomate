# Version 1.16.0 (2026-07-06) - 1.16.5 (2026-09-01)

## Editor

Using .NET 10.

Improved in **NuGet** tool:
- Restores old folder contents if failed to install/update.
- Can update dlls that are currently loaded in script processes.

New in **Help** panel:
- Favorites. Right-click...
- In web browser opens local pages by default.

(1.16.2) All LA and LA-generated programs now use standard apphost (the `.exe` file) and `.json` files, just like programs created in Visual Studio. The previously used custom apphost was more likely to trigger antivirus false positives. Also now the "missing .NET Runtime" dialog is better.

(1.16.2) Role `exeProgram` programs, if compiled or once executed in portable LA and are in the same drive and later not moved, use the .NET runtime of portable LA. They can run even when started not from LA, without shared .NET runtime installed on that computer.

(1.16.4) New installer.

Fixed bugs:
- Was defined `NET8_0`.
- Some types missing in intellisense.
- The drag-drop-file menu disappears.
- (1.16.1) Fails to load some dependencies in `editorExtension` scripts.
- (1.16.2) Cannot create 32-bit programs in 1.16.1.
- (1.16.2) Sometimes crashes on drag-over.
- (1.16.3) Bug in 1.16.2: No WPF preview.
- (1.16.3) Bug in 1.16.2: Invalid `Environment.CommandLine` and `Environment.GetCommandLineArgs` in role `miniProgram` scripts.
- (1.16.5) Bug in 1.16.3+: Portable LA does not work on Windows ARM-64.
- Prints "Warning: Cannot watch..." when runs first time on a computer.

Removed features:
- Completion list filters, like `global using Namespace; //[filters]`.
- (1.16.5) Links to folders that already exist in the workspace.

(1.16.5) Improved:
- Management of file/folder links in workspace.
- Debugger issues in 1.16.2+.

### Breaking changes

Because of the changed apphost (see above), there are some changes, usually not important:
- Corrupted process state exceptions (like memory access violation) cannot be handled. On exception the process is terminated silently. The old apphost used an environment variable to change this default .NET behavior.
- Programs generated from role `exeProgram` scripts use 2 `.json` files created by the compiler. Like all .NET programs.
- Portable LA can't launch a role `exeProgram` script task with a different UAC integrity level (when using the `uac` property) if the program is not in the portable LA drive, unless shared .NET runtime is installed on that computer.
